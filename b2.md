# dev_b2 — Beacons mesh, apps are clients

Decided 2026-11-27. Branch `dev_b2`, from `ccr-b899b983-3z4z08` (PR #1).

## The shape

```
  phone (Android)      desktop / Pi screen  console (backup)
  Slint                Slint                ratatui
     │ room engine (Rust, MLS keys stay on the device)
     └──────────────┬──────────────┬────────────┘
                    │ client link over Tor (onion, signed device key)
              ┌─────▼─────┐   mesh    ┌───────────┐
              │  Beacon A │◄─────────►│  Beacon B │   only Beacons mesh
              └───────────┘  (Tor)    └───────────┘
```

- **Keys on the device.** Every app (phone, desktop, console) keeps its MLS state and
  seals every frame; Beacons carry sealed frames only and cannot read rooms.
- **Only Beacons mesh.** A room's Beacons keep links to each other (today's mesh code,
  moved into the Beacon). A phone attaches to one Beacon it trusts (its own or a
  friend's, by scanning its code); no Beacon, no rooms.
- **Console mode.** `enigma-tui`: rooms, chat, invitations, and a large
  **Enable Beacon** button that runs a Beacon in the same process (a Pi or a desktop).
- **Android is a client only.** It never hosts an onion: Android kills background
  services and an always-on onion would drain the battery. The desktop app can enable
  Beacon like the console.

## Crates after the split

| Crate | Has | Used by |
|---|---|---|
| `crates/enigma-core` | the room engine in Rust (ported from `packages/rakotis`): MLS steps via rotor/enigmatite, roster, history, invitations, sealing, device key | tui, desktop, Android |
| `crates/enigma-client` | the client link to a Beacon over Tor (dial, signed hello, frames in/out, reconnect) | tui, desktop, Android |
| `crates/beacon-node` | mesh between Beacons, client links in, room relay, mailboxes, invitation drops, store | `beacon` binary, tui and desktop ("Enable Beacon") |
| `crates/pharos-tor` | arti: host, dial (exists) | client, node |
| `beacon/` | the `beacon` binary: config, CLI, page, systemd | Pi |
| `crates/enigma-app` | UI-agnostic app state shared by both UIs: rooms, friends, codes, dialogs, Beacon toggle, backends (demo, real) | slint, tui |
| `apps/enigma-slint` | **the app** (Slint): desktop (Linux, Windows), Android, Pi with a screen | everyone |
| `apps/enigma-tui` | console app (ratatui), the backup for headless and SSH | Linux, Pi |
| `apps/enigma` | the Tauri/Vue app, retired once enigma-slint has parity | — |

No Tauri types below `apps/`. No UI code in crates.

## Stages

1. **Split** — move mesh, mailbox and invitation-drop code out of the Tauri app into
   `beacon-node`; Beacon runs room meshes; build and tests green.
2. **Client link** — `enigma-client` + the Beacon side (phones attach, Beacon relays to
   its mesh and keeps frames for offline clients); signed device-key hello.
3. **Room engine in Rust** — port `rakotis/useChatChannel.ts` to `enigma-core`
   (tests ported too); the Vue app keeps its screens and calls Rust.
4. **Console app** — `enigma-tui` with rooms, chat, invites, Friends, and the Enable
   Beacon button.
5. **Slint app** (decided 2026-11-27: Slint everywhere, TUI as backup) — `apps/enigma-slint`
   on `crates/enigma-app` + enigma-core + enigma-client, for desktop and Android (client
   only); desktop and Pi get Enable Beacon. The Tauri/Vue app is retired at parity.
   *Progress:* `crates/enigma-app` extracted from enigma-tui (Core state + actions,
   backend trait with DemoBackend / RealBackend stub, codes, letter avatars, EN/PL texts);
   enigma-tui runs on it. `apps/enigma-slint` (binary `enigma`): rooms + chat bubbles,
   room header with state line and ⋮ menu (Invite, Participants, Room info, Reset
   encryption, Leave, Delete), ☰ menu (New chat, Join chat, Friends, Settings), Friends
   (code, QR, check codes), Settings (nickname, language, Your Beacon card, Tor), Invite
   (QR + copy), large Enable Beacon toggle on desktop, hidden on Android; light/dark from the
   system. `--demo` works end to end; without it, "not connected yet" until stage 2 wires
   RealBackend. Android: the cdylib with `android_main` cross-builds for aarch64 (NDK 27);
   APK packaging documented, not yet run. Headless UI tests and screenshots
   (`docs/screens/slint/`) use the software renderer. Still to do: RealBackend on
   enigma-client, camera scan, persistence, images/voice, retire Tauri.
6. **Docs, security, tests** — SECURITY.md (what a Beacon now sees: which client
   devices it serves, and per room which Beacons), PROTOCOL.md, real-Tor runs.

## What changes for privacy (to write up in stage 6)

- Your Beacon learns which rooms (by id) its clients are in and when they are online;
  it still cannot read anything. A friend's Beacon learns the same about you.
- Beacons of one room see each other's onions; phones' IP addresses are never seen
  by anyone (phones only dial out over Tor).
